MP Server:
  Configuration for the ZMQ multiprocess cache server

  --instance-id INSTANCE_ID
                        Stable identity of this MP server. Used as the
                        coordinator membership key and as the OTel
                        'service.instance.id' resource attribute on every
                        metric and span. Defaults to a random UUID v4 minted
                        at startup.
  --host HOST           Host to bind the ZMQ server. Default is localhost.
  --port PORT           Port to bind the ZMQ server. Default is 5555.
  --chunk-size CHUNK_SIZE
                        Chunk size for KV cache operations. Default is 256.
  --max-workers MAX_WORKERS
                        Base number of worker threads for both GPU and CPU
                        pools. Default is 1. Can be overridden per-pool with
                        --max-gpu-workers and --max-cpu-workers.
  --max-gpu-workers MAX_GPU_WORKERS
                        Worker threads for the GPU affinity pool
                        (STORE/RETRIEVE). Defaults to --max-workers if not
                        specified.
  --max-cpu-workers MAX_CPU_WORKERS
                        Worker threads for the normal CPU pool (LOOKUP, etc.).
                        Defaults to --max-workers if not specified.
  --hash-algorithm HASH_ALGORITHM
                        Hash algorithm for token-based operations (builtin,
                        sha256_cbor, blake3). Default is blake3.
  --engine-type {default,blend,blend_legacy}
                        Cache engine backend type. 'default' uses standard
                        prefix caching; 'blend' selects CacheBlend V3 (the
                        current implementation); 'blend_legacy' selects the
                        original CacheBlend. Default is 'default'.
  --supported-transfer-mode {lmcache_driven,engine_driven,auto}
                        Supported transfer mode: 'lmcache_driven' for server-
                        driven transfer (STORE/RETRIEVE, supports CUDA IPC and
                        CPU SHM), 'engine_driven' for engine-driven transfer
                        (PREPARE/COMMIT), or 'auto' to enable both transfer
                        paths. Default is 'lmcache_driven'.
  --runtime-plugin-locations [RUNTIME_PLUGIN_LOCATIONS ...]
                        Paths to runtime plugin scripts or directories to
                        launch alongside the server.
  --runtime-plugin-config RUNTIME_PLUGIN_CONFIG
                        JSON string of extra key-value config forwarded to
                        runtime plugins via
                        LMCACHE_RUNTIME_PLUGIN_EXTRA_CONFIG. Example:
                        '{"plugin.frontend.heartbeat_url":
                        "http://localhost:5000/heartbeat"}'
  --shm-name SHM_NAME   SHM segment name for engine-driven KV transfer.
                        Default "" (not specified): disable SHM. Set to a name
                        to create and use that specific SHM segment. (Only use
                        this for engine_driven transfer mode, see
                        `--supported-transfer-mode`.)
  --script-allowed-imports [SCRIPT_ALLOWED_IMPORTS ...]
                        Python modules that the /run_script endpoint is
                        allowed to import. Example: --script-allowed-imports
                        numpy pandas
  --separate-object-groups, --no-separate-object-groups
                        Split kernel groups into one object group per sliding-
                        window size at KV-cache registration (for hybrid
                        models). (Default is False)
  --worker-reap-timeout-seconds WORKER_REAP_TIMEOUT_SECONDS
                        Silence budget (s) before a ping-proven worker's KV
                        cache registration is reaped. 0 disables reaping. Must
                        be >= 3 x the engine adapter's heartbeat interval.
                        Default is 120.
  --worker-registration-grace-seconds WORKER_REGISTRATION_GRACE_SECONDS
                        Silence budget (s) for a worker that registered but
                        never pinged (model warmup or early death). Must be >=
                        the worker reap timeout. Default is 3600.
  --enable-segmented-prefix
                        CacheBlend (--engine-type blend) only: on a mid-prefix
                        L2 retrieve failure, retain the gapped prefix so post-
                        gap chunks stay L1-resident instead of truncating at
                        the gap. No effect otherwise.
  --enable [ENABLE ...]
                        List of experimental transfer modules to enable.
                        Options: transfer_query (see lmcache.v1.multiprocess.m
                        odules.experimental.__init___.py).

GDS L1 tier:
  Configuration for the GDS L1 tier. Setting --gds-l1-path makes the L1
  medium an NVMe slab accessed via GPUDirect Storage DMA instead of pinned
  DRAM; --l1-size-gb then sizes the slab. cuFile and hipFile use a slab
  file, while uGDS uses a dedicated raw device. Disable byte-array L2
  adapters when this is on.

  --gds-l1-path GDS_L1_PATH
                        NVMe directory for cuFile/hipFile, or /dev/ugds_drvX
                        for uGDS. Setting this enables GDS L1.
  --gds-l1-use-direct-io, --no-gds-l1-use-direct-io
                        Open the slab file with O_DIRECT (required for the GDS
                        DMA fast path on ext4). Default True.
  --gds-l1-backend {auto,cufile,hipfile,ugds}
                        GDS implementation. auto selects cuFile on CUDA or
                        hipFile on ROCm; ugds can be used on either platform
                        with a matching libugds.so and treats --gds-l1-path as
                        /dev/ugds_drvX.

L2 Policies:
  Store and prefetch policy selection for L2 adapters

  --l2-store-policy {default,skip_l1}
                        L2 store policy. Determines which adapters receive
                        each key and whether keys are deleted from L1 after L2
                        store. Default is 'default' (store all keys to all
                        adapters, keep L1).
  --l2-prefetch-policy {default,retain}
                        L2 prefetch policy. Determines which adapter loads

                        Maximum number of concurrent prefetch requests.
                        Default is 8.
  --periodic-notifier-interval-ms PERIODIC_NOTIFIER_INTERVAL_MS
                        Interval in ms for the periodic event notifier

GC Monitoring:
  Time CPython garbage collections so their pauses can be correlated with
  request tail latency

  --enable-gc-monitor   Time every CPython garbage collection and log the slow

  --gc-monitor-min-pause-ms GC_MONITOR_MIN_PAUSE_MS
