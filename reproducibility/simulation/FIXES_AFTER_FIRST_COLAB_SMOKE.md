# Fixes after the first Colab smoke run

## 1. Balanced capped smoke sampling

The first cap used `test_events[:20]`, evaluating only the first two of three
test documents. `balanced_event_sample` now round-robins across
`(document, query_type)` buckets and deterministically shuffles the selection.

## 2. Transferable transition baseline

The old transition baseline memorized exact chunk-ID transitions. Held-out
documents necessarily have new IDs, producing zero recall. The new
`relative_offset_transition` learns within-document offsets such as `+1`, `+2`,
or `-1` on train and applies that pattern to unseen test IDs. The exact-ID class
is retained only as `chunk_id_transition_nontransferable` for history.

## 3. Candidate-universe logging

Every policy with a defined candidate pool now reports
`candidate_coverage` and `candidate_universe_size`. This separates ranking
failure from missing graph reachability and reveals when Top-M plus two-hop
traversal becomes almost global.

## 4. Precise oracle naming

The former `oracle` knew only the immediate target. It is now named
`one_step_target_oracle`: a prediction-recall upper bound, not an optimal
future-aware cache-placement policy.

## 5. Stronger, scale-stable online update

The deployable online policy maintains one global vector:

```text
w = [semantic_weight, structural_weight]
```

Candidates are ranked with `score = w dot features`, and top-K is issued before
the target is visible. After target revelation:

1. A top-K hit causes no update.
2. A target outside the graph candidate universe is a coverage miss; weights
   cannot repair a missing edge, so there is no update.
3. Otherwise, compare the target feature with the highest-ranked wrong feature.
4. Normalize their difference so eta has a stable meaning across feature scales.
5. Apply and project the perceptron-style update:

```text
direction = normalize(phi(target) - phi(wrong))
w = ProjectSimplex(w + eta * direction)
```

Projection guarantees nonnegative weights summing to one. Cache eviction,
deadline, and transfer failures never change weights.

- `adaptive_offline_global` learns on train and then freezes.
- `adaptive_online_warm` starts from those weights and updates after reachable
  test-stream mistakes. This is the recommended main adaptive method.

Eta candidates are now `{0.01,0.05,0.1,0.2,0.5,1.0}`. Prequential dev recall
is primary; same-event post-update correction only breaks an exact tie.

## 6. Stress smoke

`--stress-smoke` uses a two-entry cache and deadline prefetching, exercising
demand eviction and late-prefetch output paths outside unit tests.

## 7. Full 600-query compatibility ablation

`--full-comparison-600` implements:

```text
test events: 600
semantic: 150
structural: 150
multi-hop: 300
K: 3,4,5,6,8,10,12,14,16
entry capacity: 16
seed: 42
```

It additionally creates 600 train and 200 dev events on disjoint documents.
The corpus remains near the old 100k-character scale while preserving document
boundaries. Checkpoints occur every 25 events for efficient exact-block resume.

This remains a comparison diagnostic: targets are created using cosine and
position rules. Final publication evidence still requires independent traces
or gold transitions not generated by the evaluated policy signals.
